# 在线文档交付限制与替代方案

## 结论

在线表格（企业微信文档、飞书表格等）不适合用桌面自动化批量插图。优先交付本地文件或截图文件夹，让用户手动插入；不要在一个不可控的共享文档上反复尝试。

## 已验证的限制

- **canvas 渲染**：表格网格不在无障碍树里，自动化只能看到浏览器外壳和按钮，无法按单元格定位。
- **菜单可点、结果不可控**：可以点开「插入」菜单，但后续的选择文件、确认插入依赖系统对话框或 canvas 内部状态，无法稳定完成。
- **系统文件选择器**：macOS 原生「打开」面板不接受自动化的坐标点击与键盘输入，`Cmd+Shift+G` 前往文件夹同样无效。
- **剪贴板图片**：在线表格不接收粘贴的图片，粘贴后无任何变化。
- **导入表格**：通常只在新建时可用，会生成一个新文档，不能填充现有文档。
- **企业微信 App 多进程**：桌面自动化可能报 `multiple processes matched app_id`，用 bundle id 或 pid 都无法绕过；此时换单进程的浏览器或直接放弃该通道。
- **文档窗口可读不可操作**：Accessibility 树里能读到窗口标题和静态文本，但单元格与工具栏不可交互。

## 推荐交付方式

按优先级：

1. **本地 xlsx，已内嵌图片**：用户在企业微信/飞书里新建并导入，42 张图随文件带入；导入后可能需要替换旧标签页。
2. **截图文件夹 + 行号对照 CSV**：用户手动「插入 → 批量插入图片」，单行多图用「单元格图片」逐张插入。文件夹只放截图，避免在几百个文件里找。
3. **仅截图 + 说明**：最差方案，容易错行。

## 交付物准备

```text
wecom_shots/
  row10_1.png
  row10_2.png
  ...
截图行号对照.csv   # 行号,功能名,截图文件
```

- 截图文件名直接带表格行号，减少用户对照成本。
- CSV 用 UTF-8 BOM，避免 Excel 打开乱码。
- 交付时明确说明：哪些是真实截图、哪些是 mock、哪些行只能文字说明。

## 如果需要人工配合

明确告诉用户需要做什么、在哪一步、大概几步完成，不要只说「自动化不行」。例如：选中 D 列单元格 → 插入 → 批量插入图片 → 选择 `~/Downloads/wecom_shots` 下的文件。
