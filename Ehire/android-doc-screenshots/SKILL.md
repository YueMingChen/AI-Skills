# Android 文档功能截图

通用流程：真机复现、mock 兜底、截图校验、原图嵌入 xlsx。页面路径、mock 属性名、场景清单属于项目差异，放在项目级 adapter skill 里；首次在新项目使用时先确认这些信息。

## 0. 前置确认

- `adb devices -l` 有设备，且 App 已登录有权限的账号。部分功能与账号身份、会员态、实名状态绑定，换账号可能直接改变页面结构。
- 确认当前构建变体和模块来源。多模块聚合项目如果通过 AAR 依赖业务模块，要确认本地源码是否真的参与编译，否则改的代码不进包。
- 内网仓库不可达时用离线构建（如 `--offline`）。
- 安装被系统拦截时（`INSTALL_FAILED_ABORTED`），在设备上手动确认继续安装。

## 1. 先定文档锚点，再截图

- 文档可能已被他人改过行结构（插入、删除、合并）。**行号会变，图片锚点不会跟着行移动**。
- 开始前先读当前表格：逐行输出功能名等文本列，与截图文件 `rowNN_k.png` 建立映射，不要沿用上一次的行号记忆。
- 在线文档与本地文件结构不一致时，以功能名匹配，不要按行号硬对。
- 任何行结构变更后，所有已嵌图片都要重新嵌入并回归校验。

## 2. 真机采集

推荐写一个小脚本串起固定动作，避免手工点错：

```bash
# 1) 回到入口页（逐级返回）
adb shell input keyevent 4
# 2) 设置 mock 场景
adb shell setprop debug.<project>.mock <scene>
# 3) 进入目标页面（坐标或固定入口）
adb shell input tap <x> <y>
# 4) 等页面渲染完成
sleep 3
# 5) 截图
adb exec-out screencap -p > rowNN_k.png
```

- 文件名统一 `rowNN_k.png`（表格行号 + 该行第几张），便于嵌图脚本和人工核对。
- 截图前确认接口已返回、页面已渲染，否则容易截到骨架屏或 loading。
- 每次操作前检查设备连接，设备可能中途掉线。
- 入口页不稳定时，优先用「返回直到某个锚点文本出现」而不是固定返回次数。

## 3. Mock 场景约定

- 用系统属性传场景，属性名必须带 `debug.` 前缀（`setprop` 只允许白名单前缀）。项目自定义完整属性名，例如 `debug.<project>.mock`。
- 读取必须实时反射系统属性：

```kotlin
Class.forName("android.os.SystemProperties")
    .getMethod("get", String::class.java, String::class.java)
    .invoke(null, "debug.<project>.mock", "") as? String
```

  `System.getProperty` 只在进程启动时写入，`setprop` 之后不会刷新，不要用。
- 不要依赖 App 私有目录里的场景文件或 SharedPreferences 做场景开关，进程重启和权限问题都会让行为不可控。
- 所有 mock 分支必须只在 debug 包生效（`BuildConfig.DEBUG`），正式包直接返回空场景。
- 场景集中在一个入口分发，不要散落在各页面。触发时机放在目标页面数据就绪之后：
  - 弹窗/浮层：`postDelayed` 等渲染完成再弹。
  - Activity：直接 `startActivity`。
  - 列表/接口数据：在请求成功回调里改数据再 `postValue`。
- 数据类场景（权限态、实验分组、付费态）优先改 ViewModel/PresenterModel 的字段或判断分支，复用真实 UI，不要伪造整页。

## 4. 先判定能否出图

- 有独立页面、弹窗、浮层：截图。
- 纯交互（滑动联动、页面内点击跳转）、协议桥、路由配置、灰度开关、埋点：没有独立界面，在截图列写文字说明，不要硬造截图。
- 依赖实验分组的（按钮 AB、会员实验）：当前账号未命中时，在 debug 分支强制目标分组，并在文档备注注明是 mock 分组。
- 依赖服务端数据的（附件、导出、礼包、邀约）：优先复用真实组件 + 本地预置数据，保证截图里是真实页面结构。
- 设计稿/标注图只能作为最后兜底，且必须在文档里注明来源。

## 5. 截图有效性校验

```bash
adb shell uiautomator dump /sdcard/ui.xml >/dev/null 2>&1
adb shell cat /sdcard/ui.xml > /tmp/ui.xml
# 用项目已有的 XML 解析脚本或 grep 预期文案
```

- WebView、H5、系统弹层可能不在 UI 树里，以截图内容人工确认为准，不要因为 dump 不到就判定失败。
- 多图行要逐张确认文件名与内容一一对应，避免 A 场景图放进 B 行。
- 嵌入 xlsx 后再次校验：读取截图列每张图的锚点行，反查对应图片文件并比对哈希，确认没有被旧图覆盖。

## 6. 写入 xlsx

- 原图无损嵌入，不做压缩；显示尺寸要小（经验值 30px 宽），保持原始宽高比。
- 用 `OneCellAnchor` 控制位置，锚点列固定为截图列，加少量 `rowOff/colOff` 避免贴边。
- 同一单元格多张图横向并排；按该列最多张数计算列宽，不要压到相邻列。
- 只改截图列与列宽，其他列和合并区域保持原样。
- 具体代码和校验方法见 `references/xlsx-embed.md`。

## 7. openpyxl 与在线文档的坑

- `range_boundaries()` 返回顺序是 `(min_col, min_row, max_col, max_row)`，参数写反会清空数据。
- `insert_rows/delete_rows` 不会移动图片锚点、行高、合并区域，必须手工补偿。
- 改表前先备份；改完后逐格比对非截图列，确认无差异。
- 在线文档（企业微信、飞书等）多为 canvas 渲染，桌面自动化难以可靠点击网格；系统「打开」文件面板通常也不接受自动化的坐标点击和键盘输入。不要在在线文档上反复硬试。
- 在线文档的「导入表格」一般只会新建文档，不能填充现有文档。
- 更稳的交付：导出按行号命名的截图文件夹 + 行号对照 CSV，让用户用「插入 → 批量插入图片」手动完成，或改用导入本地 xlsx。细节见 `references/online-doc-delivery.md`。

## 8. 交付与清理

- 交付前确认：截图行覆盖完整、无错位、非截图列未变、合并区域未变。
- Mock 调试代码（场景分发、debug 属性读取、代理注入、内置证书）属于验证代码，合入前必须移除或隔离，并在交付说明里列出。
- 清理设备侧残留：场景属性、预置 mock 文件、代理设置。
- 最终说明写清：哪些行是真实截图、哪些是 mock 数据、哪些只能文字说明、哪些未覆盖及原因。
